# SPC 설명기 설계

- 작성: 2026-09-25
- 상태: 대화에서 설계 승인 → 구현 계획(writing-plans) 단계
- 근거 자료: `docs/brief.md`, `docs/research/2026-09-24-spc-library-comparison.md`

## 1. 목적과 성공 기준

SK하이닉스 AI 해커톤 2026 지원용 포트폴리오다. 마감은 9/28(월) 17시, 구현은 9/26까지 끝낸다.

반도체 공정 엔지니어는 관리도를 눈으로 보고 이상을 판단하고, "무엇부터 점검할지"는 경험에 의존한다.
이 앱은 규칙 엔진이 이상을 판정하고, LLM이 그 판정을 받아 "어떤 패턴인지 / 무엇부터 점검할지 / 근거 규칙"을 한국어로 설명한다.

성공 기준:
1. 배포된 Streamlit 앱에서 20개 시리즈의 판정·설명·검증 리포트를 API 키 없이(캐시로) 볼 수 있다.
2. 검증 리포트에 다음 수치가 있다: 규칙 탐지율과 오탐, LLM 단독 판정 비교(모델별), LLM 설명의 JSON 형식 위반·원인표 밖 원인·판정 불일치.
3. 모든 수치는 스크립트 한 번으로 재현된다 (고정 시드, 결과 파일 커밋).
4. LLM이 틀린 출력은 `docs/ai_errors.md`에 남는다.

## 2. 핵심 원칙

- **판정 = 규칙, 설명 = LLM.** 설명 LLM에는 원시 시계열을 주지 않고, 규칙 판정 결과(JSON)와 원인표만 준다. 설명이 판정과 어긋나면 "판정 불일치"로 기록하고, 화면은 항상 규칙 판정을 기준으로 표시한다.
- **관리한계 고정값 사용 = 이미 안정화된 공정을 감시하는 상황(Phase II)을 가정한다.** 중심선 100nm, UCL 103nm, LCL 97nm(σ=1nm, ±3σ)를 고정으로 쓰고, 합성 데이터에서 한계를 다시 추정하지 않는다. (SECOM만 예외: 목표값이 없어 앞 구간에서 추정한다 — 7절)
- **캐시 우선.** LLM 결과는 커밋된 `results/*.json`을 먼저 보여주고, 실시간 호출은 횟수를 제한한다.
- **실패를 숨기지 않는다.** 오탐, LLM 오류, 반복 간 차이를 그대로 보고한다. 실험은 특정 결론을 전제하지 않고, 규칙과 LLM을 같은 기준으로 잰다.

## 3. 판정 규칙 (3패턴)

| 패턴 | 코드 | 정의 | 방향 |
|---|---|---|---|
| 급변 | `spike` | 한 점이 UCL 초과 또는 LCL 미만 | 위 / 아래 |
| 추세 | `trend` | 연속된 6개 이상의 점이 매번 직전 점보다 커짐(작아짐) = 5회 이상 연속 증가(감소) | 상승 / 하강 |
| 치우침 | `shift` | 연속된 9개 이상의 점이 모두 중심선 위(아래) | 위 / 아래 |

- 엔진: pycontrolcharts 0.1.2의 `run_tests_with_custom_limits`
  - `RunTestConfig(test1=True, test2=True, test3=True, test5=False, test6=False, test2_n=9, test3_n=5)`
  - `test3_n`은 "점 개수"가 아니라 "증가 횟수"다. 기본값 6은 7점을 요구하므로, 브리프의 "6점 연속 상승/하강"에 맞춰 5로 둔다. (2026-09-25 확인: `test3_n=5`에서 6점 상승은 탐지, 5점 상승은 미탐. shewhart `nelson_3`과 같은 정의)
  - 위반 type 코드: 1/2 = UCL 초과/LCL 미만, 3/4 = 9점 중심선 위/아래, 5/6 = 연속 증가/감소
- 사건(event) 정규화: 같은 (패턴, 방향)으로 표시된 연속된 점들을 사건 하나 `[start, end]`로 묶는다. 추세는 라이브러리가 둘째 점부터 표시하므로 start를 1 앞당겨 런 전체를 사건으로 삼는다.
- 교차 검증: shewhart 0.1.1(개발 전용 의존성)로 같은 데이터를 판정해, 두 엔진의 사건이 일치하는지 테스트한다.
- 점 번호는 코드·JSON·프롬프트·화면 모두 **0부터** 센다.

## 4. 가상 데이터

- 20개 시리즈 × 100점, 고정 시드(`20260925`).
- 정상 점은 N(100, 1²). 관리한계의 σ와 같으므로 정상 구간에서도 자연 오탐이 생길 수 있고, 그대로 보고한다.
- 시나리오 표 (고정):

  | 시리즈 | 심은 이상 |
  |---|---|
  | 0–4 | 없음 (정상 5개) |
  | 5–7 | 급변 |
  | 8–10 | 추세 |
  | 11–13 | 치우침 |
  | 14–15 | 급변 + 추세 |
  | 16–17 | 급변 + 치우침 |
  | 18–19 | 추세 + 치우침 |

  패턴별 7개, 총 21개.
- 이상은 규칙 정의를 **반드시 만족하도록** 심는다. 심은 이상이 데이터에 실제로 있으므로, 탐지 실패는 판정하는 쪽의 실패로 해석할 수 있다.
  - 급변: 1점. 방향 무작위, 값 = 100 ± U(3.5, 5.0).
  - 추세: 8점. 방향 무작위. 시작값 = 100 ∓ U(1.0, 1.5), 총 변화량 U(2.5, 3.5)를 양수 7구간으로 나눠 엄격한 단조 증가(감소)로 만든다. 한계 안에 머문다.
  - 치우침: 10점. 방향 무작위. N(100 ± 1.5, 1²)에서 뽑되, 중심선 한쪽이면서 한계 안(100~103 또는 97~100)에 드는 값만 쓴다(기각 표집).
  - 위치: 무작위. 앞 10점은 항상 정상으로 두고, 이상끼리는 10점 이상 떨어뜨린다.
- 저장: `data/synthetic/series.json` (값, 정답 라벨, 시드). 커밋한다.

## 5. 채점 방법 (규칙·LLM 공통)

- 겹침: 구간 `[s1, e1]`과 `[s2, e2]`가 한 점이라도 겹치면(`s1 <= e2 and s2 <= e1`) 겹친 것으로 본다. 허용 오차는 두지 않는다.
- 탐지: 정답 이상마다, 같은 패턴의 탐지 사건이 겹치면 "탐지".
- 탐지 사건 분류:
  - 정탐: 같은 패턴의 정답과 겹침
  - 패턴 혼동: 다른 패턴의 정답과만 겹침
  - 오탐: 어떤 정답과도 겹치지 않음
- 보고:
  - 탐지율: 패턴별(탐지 수/7), 전체(탐지 수/21)
  - 오탐은 따로 보고한다. 정상 시리즈 5개는 "경보가 난 시리즈 수 / 5"와 패턴별 오탐 사건 수, 이상 시리즈는 오탐 사건 수와 패턴 혼동 수.

## 6. LLM

### 6.1 모델 설정 (`spc_explainer/config.py` 한 곳에서 관리)

| 용도 | 모델 | temperature | 반복 | 기본 |
|---|---|---|---|---|
| 설명 | `gpt-4.1-mini` | 0 | 3 | 켬 |
| 단독 판정 | `gpt-4.1-mini` | 0 | 3 | 켬 |
| 단독 판정 | `gpt-6-sol` | 기본값(1) | 3 | 켬 |
| 단독 판정 | `gpt-6-astra` | 기본값 | 1 | **끔** |

- 2026-09-25 확인: 이 키로 보이는 모델은 `gpt-4.1-mini`, `gpt-6-sol` 둘이다.
- `gpt-6-sol`은 temperature 0을 거부한다("Only the default (1) value is supported"). 그래서 temperature는 모델별 설정으로 두고, 지원하는 모델은 0(LLM에 가장 유리한 조건)으로 둔다.
- `gpt-6-astra`는 아직 비활성이라 기본값을 끔으로 둔다. 쓰려면 OpenAI 대시보드에서 허용한 뒤 config에서 켠다. 켜면 단독 판정 비교에만 1회 들어간다.
- 호출: OpenAI Chat Completions + JSON 모드(`response_format={"type": "json_object"}`).
  - strict JSON 스키마는 쓰지 않는다. 형식 위반과 원인표 밖 원인을 측정하려면 모델이 틀릴 여지가 있어야 하기 때문이다. 대신 자체 검증기가 모든 출력을 검사한다. (운영용 강화안: strict 스키마 + 원인 id enum — 리포트에 적는다)
- 재시도: 네트워크·429·5xx 같은 API 오류만 SDK 재시도(최대 3회). 형식이 틀린 응답은 재시도하지 않고 그대로 기록한다.

### 6.2 설명 (`gpt-4.1-mini`)

- 입력
  - 공정 정보: 증착 막 두께, 목표 100nm, 관리한계 97~103nm
  - 규칙 사건 목록(JSON): 사건 id(`E1`, `E2`, …), 패턴, 방향, 구간, 근거 규칙 문장, 요약 수치(급변은 값, 추세는 시작·끝 값, 치우침은 평균)
  - 사건에 나온 패턴의 원인표 행
  - 원시 시계열은 주지 않는다.
- 사건이 없는 시리즈는 LLM을 호출하지 않고 "이상 없음"을 표시한다.
- 출력 JSON:

  ```json
  {
    "summary": "43번 점이 상한을 넘었고, 60~67번에서 두께가 계속 늘었습니다.",
    "events": [
      {"event_id": "E1", "pattern": "급변", "rule": "관리한계 밖 1점 (43번 104.1nm > UCL 103nm)",
       "checks": [{"cause_id": "SP-1", "reason": "한 점만 튀었으므로 계측 오류부터 배제"}]},
      {"event_id": "E2", "pattern": "추세", "rule": "6점 이상 연속 상승 (60~67번)",
       "checks": [{"cause_id": "TR-1", "reason": "8점 동안 꾸준히 늘었으므로 챔버 누적 증착물부터 확인"},
                  {"cause_id": "TR-2", "reason": "히터 온도가 함께 변했는지 확인"}]}
    ],
    "priority": ["E2", "E1"]
  }
  ```

  `checks`는 사건별 1~3개, 점검할 순서대로. `priority`는 먼저 볼 사건 순서.
- 검증기 (출력마다 적용, 문제를 유형별로 기록)
  - JSON 형식 위반: 파싱 실패, 필수 키 누락, 타입 오류, `pattern`이 세 이름(급변/추세/치우침) 밖, `checks` 개수가 1~3 밖
  - 원인표 밖 원인: `cause_id`가 원인표에 없음, 또는 다른 패턴의 원인
  - 판정 불일치: 사건 id 누락·추가, 사건의 패턴이 규칙 판정과 다름, `priority`가 사건 id의 순열이 아님
  - 반복 간 차이(참고): 3회 중 사건별 1순위 원인이나 `priority`가 달라진 시리즈 수
- 원인표 (`spc_explainer/causes.py`): 패턴별 5개, id `SP-1~5`(급변), `TR-1~5`(추세), `SH-1~5`(치우침). 각 행은 원인과 점검 항목. 교과서 수준의 도메인 가정이며 실제 설비 데이터로 검증한 것이 아니라고 README와 리포트에 적는다.

### 6.3 LLM 단독 판정 (비교 실험)

- 목적: LLM이 판정까지 직접 할 때의 정확도와 일관성을 규칙 엔진과 같은 기준으로 잰다. 역할 분리를 할지 말지의 근거가 된다.
- 입력: 3절의 규칙 정의 그대로(추세 = 6점 이상 = 5회 이상 연속 증가를 명시), 중심선·한계, "번호: 값" 100줄.
- 출력 JSON: `{"detections": [{"pattern": "추세", "start": 60, "end": 67}]}` (없으면 빈 배열)
- 검증: 파싱 실패, 키·타입 오류, 번호가 0~99 밖, start > end이면 형식 위반. 형식 위반 출력은 탐지 0개로 채점하고 따로 센다.
- 채점: 5절과 같다. 반복별 탐지율을 모두 기록하고 평균과 최소~최대로 보고한다.

### 6.4 반복 실행과 기록

- 설명: 사건이 있는 시리즈 × 3회. 단독 판정: 20개 시리즈 × 모델별 반복 수.
- 예상 호출 수: 설명 약 50~60회, 단독 판정 `gpt-4.1-mini` 60회 + `gpt-6-sol` 60회 (+ astra를 켜면 20회).
- 결과는 원문과 함께 `results/*.json`에 저장하고 커밋한다. 모델명, temperature, 프롬프트 버전, 응답 시간, 토큰 사용량을 함께 남긴다.
- 캐시: (모델, 시리즈, 반복 번호, 프롬프트 버전, 입력 해시)가 같은 결과가 있으면 다시 호출하지 않는다. 중단 후 재개와 비용 절약용이다. `--force`로 강제 재호출.
- `docs/ai_errors.md`: 틀린 출력을 실행 단위 섹션으로 **추가**한다(덮어쓰지 않음). 항목은 구분(설명/단독 판정), 모델, 시리즈, 반복, 유형, 틀린 점, 출력 발췌. 입력은 시리즈 번호와 시드로 재현할 수 있고, 전체 출력은 같은 커밋의 `results/*.json`에 있다. 캐시에서 꺼낸 결과는 이미 기록됐으므로 다시 적지 않는다.

## 7. SECOM 실데이터 확인

- 출처: UCI SECOM. 센서 590개 × 1567건, pass/fail 라벨(불량 104건), 2008-07-19 ~ 2008-10-17. CC BY 4.0, DOI 10.24432/C54305. README에 출처를 표기한다.
- 센서 선정 (불량 라벨은 쓰지 않는다 — 결과를 보고 고르는 것을 막기 위해):
  전체 결측 0개 + Phase I 고유값 200개 이상 + Phase I 왜도 절댓값 0.5 이하 → 번호 순으로 앞 2개.
  2026-09-25 확인 결과: 센서 88, 115.
- Phase I = 시간순 앞 500점. 중심선 = 평균, σ = 평균 이동범위 / 1.128, 한계 = 중심선 ± 3σ.
- Phase II = 나머지 1067점을 같은 규칙 엔진으로 감시한다.
- 보고: 정답이 없으므로 탐지율은 계산하지 않는다.
  - 작동 확인: 패턴별 알람 사건 수
  - 불량 라벨과의 겹침 관찰: 불량 점을 포함한 알람 사건 수, 알람 점 중 불량 비율과 Phase II 전체 불량 비율
  - 인과나 탐지 성능으로 해석하지 않는다고 명시한다.
- LLM 설명은 붙이지 않는다. 원인표가 증착 공정 기준이라 익명 센서에는 맞지 않는다.
- 저장: `scripts/fetch_secom.py`가 원본을 받아 선정 센서만 `data/secom/secom_selected.csv`로 저장하고 커밋한다. 앱은 실행 중에 다운로드하지 않는다.

```
  ui_html.py, ui_steps.py,    화면 조각: 전역 CSS·머리말·가이드·섹션 / 규칙 판정·AI 설명 카드·사건 선택 /
  ui_dashboard.py               04 검증 지표 가공 (순수 함수, pytest로 확인)

```

- 의존 방향: `config` ← `patterns` ← `generator`·`rules`·`matching` ← `explain`·`llm_detect`(← `llm_client`, `causes`) ← `experiment` ← `report`.
- LLM 호출이 필요한 함수는 호출 함수를 인자로 받는다. 테스트는 가짜 함수를 넣어 네트워크 없이 돈다.
- 앱은 결과 파일을 읽고, 규칙 판정은 그 자리에서 다시 계산한다(빠르고 결정적). 실시간 설명 버튼만 `explain` + `llm_client`를 쓴다.

## 9. 화면 (Streamlit)

한 페이지 스토리형(Claude Design 2A, 2026-09-26 사용자 채택). 탭을 쓰지 않고 위에서 아래로 읽는다. 모바일(2B)은 같은 페이지의 반응형 CSS.

- 머리말: 원칙 한 문장 + ① 규칙 판정 → ② AI 설명 → ③ 검증 흐름 + 관리 기준(CL·UCL·LCL)과 고정 한계 가정
- 첫 방문 30초 가이드: 머리말 아래 3단계(시리즈 고르기 → 판정 보기 → 설명·검증 보기). 닫으면 세션 동안 유지
- 01 문제 상황: 엔지니어가 관리도를 보고 경험으로 점검 우선순위를 정한다는 문제
- 02 규칙 판정
  - 시리즈 선택(20개, 정상/심은 이상 표시)
  - 관리도: 점, 중심선, UCL/LCL, 규칙 사건을 패턴별 색·기호로 표시, 정답 구간은 점선 테두리(토글)
  - 점 클릭 → 그 점이 속한 사건을 골라 03의 설명·체크리스트에서 강조·펼침(재그리기는 이 섹션만). 사건 밖의 점이면 "이 점은 판정된 사건에 속하지 않습니다". 휴대폰 터치로 점 선택이 안 될 수 있어 사건 선택 드롭다운을 함께 둔다
  - 규칙 사건 표(패턴·구간·판정 근거·규칙 번호)
- 03 AI 설명
  - 캐시된 설명(1회차) + 검증 배지(통과 / 문제 목록), "3회 반복 보기"
  - "실시간 설명 받기" 버튼: `gpt-4.1-mini`만, 세션당 3회·서버 하루 50회. 키가 없으면 비활성.
  - 지금 확인할 것: 사건마다 체크리스트. 항목은 원인표에서만 가져오고(LLM이 항목을 만들지 않음), 검증을 통과한 AI 설명이 있을 때만 그 점검 순서를 앞에 둔다(AI 추천 n순위). 판정 요약·설명·체크리스트를 .md로 내려받거나 텍스트로 복사(교대 인수인계용)
  - 사건마다(06 업로드 사건 포함) "오탐이에요" 버튼. 세션 상태에만 모으고 목록·CSV 내려받기 제공. "시연용: 실제 운영에서는 이 피드백으로 규칙·원인표를 개선한다" 표기
- 04 검증: 규칙 판정 vs 모델별 LLM 단독 판정 (KPI, 패턴별 탐지율 막대, 수치로 본 사실), AI 오류 유형별 개수(자동 집계), 사례 해설(수동 분석, `docs/case_notes.md` — 자동 집계와 표기를 구분), 설명 LLM 오답 목록
- 05 실데이터 확인 (SECOM): 센서 선택, Phase I/II 경계, 한계, 알람 사건, 불량 라벨 표시, 요약 수치
- 06 내 데이터로 판정: CSV 올리기 또는 붙여넣기. 숫자 열 1개(막 두께), 앞에 시점 열은 선택, 최대 2,000행. 결측·문자·빈 파일·열 수 오류는 몇째 줄인지 알려 주며 거절. 파일은 저장하지 않는다(안내 문구, AI 설명을 받으면 판정 요약이 OpenAI로 간다는 것도 표시)
  - 관리한계: (a) 앞 N점으로 추정(SECOM과 같은 Phase I 방식, N 기본값 = 행 수의 절반과 100 중 작은 값, 최소 20, 감시할 점 10개 이상 필요) 또는 (b) 중심선·UCL·LCL 직접 입력(LCL < CL < UCL)
  - 판정은 기존 규칙 엔진 그대로. AI 설명은 실시간 호출만 하고 03과 같은 호출 한도를 쓴다. 체크리스트도 같은 방식
  - 예시 CSV(가상 시리즈 11) 내려받기. 결과는 04 검증 수치에 섞지 않는다
- 07 한계: 가상 데이터, 06 판정은 참고용, 원인표 가정, 작은 표본, SECOM은 관찰일 뿐임
- 맨 아래: 전체 검증 리포트(`docs/validation_report.md`) 펼치기
- 용어 툴팁: UCL/LCL, 중심선, σ, 급변·추세·치우침, 오탐에 한 줄 설명. 데스크톱은 마우스를 올리면, 휴대폰은 탭하면 뜬다. 문구는 `glossary.py` 한 곳
- 성능: 결과 파일 읽기와 SECOM 계산은 캐시하고, 시리즈·센서·올린 데이터를 바꾸면 그 섹션만 다시 그린다.
- 결과 파일이 없거나 캐시에 저장된 판정 입력이 현재 판정과 다르면 경고만 띄우고 앱은 계속 동작한다.

## 10. 오류 처리

- API 키 없음: 캐시로 전부 동작하고 실시간 버튼만 비활성.
- API 호출 실패: 재시도 후에도 실패하면 "호출 오류"로 기록(형식 위반과 구분)하고 실험은 계속한다.
- LLM 출력 검증 실패: 화면에 배지로 표시한다. 판정은 항상 규칙 기준.
- SECOM 파일 없음: 05 섹션에 안내 문구를 띄운다.
- 06 입력 오류(결측, 숫자가 아닌 값, 빈 파일, 열 수, 행 수, 인코딩, 한계 순서): 몇째 줄인지 포함한 한국어 문장으로 거절하고 화면은 계속 동작한다. 사용자가 올린 글자는 이스케이프해서 보여준다.
- API 키는 로컬 `.env`, 배포는 Streamlit Secrets에서만 읽는다. 결과 파일·로그에 키를 남기지 않는다.

## 11. 테스트

pytest, 네트워크 호출 없음.

- generator: 같은 시드면 같은 결과, 정상 5개에 이상 없음, 각 이상이 규칙 정의를 만족, 이상끼리 안 겹침
- rules: 방향별 type 매핑, 사건 묶기, 추세 start 보정, 6점 추세 탐지·5점 미탐, 20개 시리즈에서 shewhart와 사건 일치
- matching: 겹침 판정, 정탐·패턴 혼동·오탐 분류, 집계
- explain 검증기: 정상 출력, 깨진 JSON, 키 누락, 원인표에 없는 id, 다른 패턴 id, 사건 누락·추가, 패턴 불일치, priority 오류
- llm_detect 파서: 정상, 번호 범위 밖, start > end, 깨진 JSON
- experiment: 가짜 LLM으로 전 과정 실행 → 결과 파일 생성, 캐시 재사용, ai_errors 추가
- secom: 이동범위 기반 σ, 선정 함수가 라벨 없이 동작, Phase II 번호 보정
- 화면 추가 기능: 체크리스트 항목이 원인표에서만 오는지, 용어 툴팁 문구·위치, 점 클릭 → 사건(AppTest에 선택 상태를 넣어 확인), 가이드 닫기 유지, 피드백 넣기·빼기·CSV, 업로드(정상 CSV, 결측, 문자, 행 초과, 한계 직접 입력, 가상 시리즈를 CSV로 넣었을 때 기존 판정과 같음)
