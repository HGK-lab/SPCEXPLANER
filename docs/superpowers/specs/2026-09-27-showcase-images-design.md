# 포트폴리오 소개 이미지 6장 — 설계

작성 2026-09-27. 브레인스토밍(시각 시안 v1~v4)에서 사용자와 정한 내용을 옮긴 것이다. 앱 코드는 동결 상태라 건드리지 않는다.

## 1. 목적과 쓰임

- 포트폴리오 PDF(사용자가 만든다)에 끼워 넣을 16:9 가로 이미지 6장. 1920×1080 PNG, 필요하면 같은 내용의 JPG.
- 메시지는 반반: 제품 흐름(판정 → 설명 → 내 데이터)과 설계 판단(AI에게 판정까지 맡기지 않은 이유를 실험으로 확인).
- 읽는 사람: 포트폴리오를 넘겨 보는 평가자. 이미지만 넘겨 봐도 "무엇을 만들었고, 왜 그렇게 나눴는지"가 전달돼야 한다.

## 2. 사용자 결정 (브레인스토밍)

- 스킬 기본 틀(휴대폰 두 대 + 떠 있는 카드), 앱 화면의 톤(회색 바탕 + 흰 카드), 단순 캡처 — 셋 다 따르지 않는다.
- 장마다 데스크톱·모바일 화면을 섞어 넣고, 구도와 바탕을 장마다 다르게 한다 (한 틀 반복 금지).
- 바탕은 어두운 계열 — 앱 화면이 라이트 테마라 캡처가 또렷하게 뜬다.
- 1번 시안(출력물 위의 메모)의 손글씨 주석을 쓴다.
- 포트폴리오 느낌. 대회·회사 이름 같은 공고 맞춤 표현은 넣지 않는다.
- AI가 만든 티를 줄인다 (아래 5절의 금지 목록).

## 3. 공통 요소 (장마다 바뀌지 않는 것은 이것뿐)

## 4. 장별 구성

|---|---|---|---|---|

### 문구 (존댓말, 만든 사람이 직접 말하는 문장)

1. 제목 "판정은 통계 규칙에 맡기고, / AI에게는 설명만 맡겼습니다". 본문 "관리도에서 이상 구간을 찾는 일은 규칙 엔진이 합니다. AI는 그 결과만 받아, 무엇부터 점검할지 순서를 붙입니다." 손글씨: #45에 빨간 동그라미 + "한계를 넘은 점은 규칙이 확정".
2. 제목 "이상 구간은 규칙이 먼저 확정합니다". 본문 "급변, 치우침, 추세 세 가지를 통계 규칙(Nelson R1~R3)으로 판정합니다. 같은 입력이면 항상 같은 결과입니다." 손글씨 "점을 누르면 그 사건이 표에서 강조".
3. 제목 "AI는 무엇부터 볼지만 알려 줍니다". 본문 "규칙이 넘긴 구간과 원인표만 받아 점검 순서를 고릅니다. 출력은 매번 형식, 원인표, 판정 일치를 검증합니다." 손글씨 "원인표 밖 원인은 검증에서 걸러요", 검증 배지 옆 "실험 출력 48개 모두 통과".
4. 제목 "AI에게 판정까지 맡겨 봤습니다". 표(찾은 이상 / 오탐 회당 평균 / 걸린 시간): 규칙 엔진 21/21 · 6건 · 0.48ms, gpt-4.1-mini 14/21 · 103건 · 2.1초, gpt-6-sol 21/21 · 6건 · 10.8초. 각주 "가상 관리도 20개, 심은 이상 21개. 시간은 규칙 엔진 시리즈 1개, AI 호출 1번 기준." 손글씨 "치우침은 7개 중 1.3개만"(gpt-4.1-mini 줄), "답은 규칙과 같다. 대신 60번에 $0.46"(gpt-6-sol 줄).
5. 제목 "가상 데이터 밖에서도 돌려 봤습니다". 본문 "공개 반도체 공정 데이터(UCI SECOM) 센서에 같은 규칙을 적용했습니다. 정답이 없어 탐지율은 따지지 않았습니다. 내 CSV를 올려도 같은 규칙으로 판정합니다." 인화지 손글씨 "SECOM 센서 88, 알람 24건", "내 CSV도 같은 규칙으로".
6. 제목 "직접 눌러 보실 수 있습니다". 본문 "배포 앱에서 시리즈를 고르고, 점을 누르고, 내 CSV를 올려 보세요. 코드와 실험 기록은 저장소에 있습니다." 주소 두 줄(배포 URL 전체, github.com/HGK-lab/SPCEXPLANER). 손글씨 "휴대폰으로도 됩니다".

## 5. 금지 목록 (AI 티·사실 오류 방지)

- 대회·회사 이름, "심사위원" 같은 공고 맞춤 표현.
- 모노 글꼴 작은 라벨, 영문 대문자 라벨, 가운뎃점으로 이은 메타 문구, "A — B" 줄표 라벨, 제목 속 한 단어만 색 강조, 알약 칩, 똑같은 둥근 카드 반복, 빛 번짐·그라데이션 장식, 네온색.
- 대구형 표어("~이. ~가."). 제목은 만든 사람이 하는 한 문장.
- 측정하지 않은 숫자, 결과 파일과 다른 숫자, 실제 화면에 없는 내용을 캡처처럼 꾸민 것. 손글씨 주석도 사실만.

## 6. 만드는 방법

- 위치: `docs/portfolio/showcase/` — `flow.json`(캡처 단계), `shots/`(원본 캡처), `slides.html`(6장), `out/`(PNG + `_overview.png`).
- 캡처: 스킬의 `capture.mjs`로 로컬 앱(streamlit)을 몰아 찍는다. 03 설명은 저장된 결과라 LLM을 부르지 않는다.
- 조판: 스킬 템플릿의 렌더 구조(`.slide` 섹션)만 빌리고, 구도·스타일은 이 문서대로 새로 쓴다.
- 렌더: 스킬의 `render.mjs` (1920×1080, 필요하면 `--jpg`).
- 캡처의 특정 점(#45 등)에 손글씨를 맞출 때는 캡처 좌표를 재서 배치한다.

## 7. 확인

- `render.mjs` 경고 0 (깨진 이미지, 잘린 글자, 슬라이드 밖 글자).
- 장마다 전체 크기로 눈 확인: 손글씨가 가리키는 대상이 맞는지, 중요한 UI가 가려지지 않는지, 한국어 줄바꿈.
- 숫자를 `numbers.md`와 한 줄씩 대조. 문구를 5절 금지 목록으로 점검.
- 6장을 나란히 놓고 "한 틀 반복"이 없는지 확인 (구도·바탕·기기 비율이 장마다 다름).

## 8. 전달과 커밋

- 결과 경로, 장마다 한 줄 설명, 에둘러 표현한 것이 있으면 그 내용을 보고한다.
- PNG를 저장소에 커밋할지는 결과를 보고 사용자에게 묻는다. `.superpowers/`(브레인스토밍 시안)는 커밋하지 않는다.
