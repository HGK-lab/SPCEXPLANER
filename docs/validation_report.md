# 검증 리포트

> 자동 생성: `python scripts/run_experiment.py` · 2026-09-25T23:48:41  
> 관리한계 고정값(중심 100nm, UCL 103nm, LCL 97nm) 사용 = 이미 안정화된 공정을 감시하는 상황을 가정한다.

## 1. 실험 조건

- 가상 데이터: 20개 시리즈 × 100점, 시드 20260925. 정상 시리즈 5개, 심은 이상 21개 (급변 7, 추세 7, 치우침 7).
- 심은 이상은 규칙 정의를 만족하도록 만들었다: 급변 = 한계 밖 1점, 추세 = 8점 연속 단조, 치우침 = 10점 연속 중심선 한쪽.
- 채점: 같은 패턴의 탐지 구간이 정답 구간과 한 점이라도 겹치면 탐지. 어떤 정답과도 겹치지 않으면 오탐, 다른 패턴의 정답과만 겹치면 패턴 혼동.

## 2. 규칙 판정

| 패턴 | 탐지 / 심은 수 | 탐지율 |
|---|---|---|
| 급변 | 7 / 7 | 100% |
| 추세 | 7 / 7 | 100% |
| 치우침 | 7 / 7 | 100% |
| 전체 | 21 / 21 | 100% |

오탐 (심은 이상과 겹치지 않는 경보):
- 정상 시리즈: 5개 중 1개에서 경보. 오탐 사건: 급변 1, 추세 0, 치우침 0
- 이상 시리즈: 오탐 사건 급변 2, 추세 2, 치우침 1. 패턴 혼동 0건
- 오탐 목록: 시리즈 3 급변 63~63번; 시리즈 7 급변 98~98번; 시리즈 11 급변 45~45번; 시리즈 11 추세 76~81번; 시리즈 12 치우침 83~92번; 시리즈 13 추세 87~92번
- 정상 점을 N(100, 1²)로 만들었으므로 정상 구간에서도 규칙 정의를 실제로 만족하는 경보가 생길 수 있다. 규칙 판정에도 오탐이 있다는 뜻이다.
- 교차 검증: 독립 구현(shewhart)과 점 단위 판정이 같은지 `tests/test_crosscheck.py`에서 확인한다.

## 3. LLM 단독 판정 비교

LLM에게 규칙 정의와 원시 데이터(번호: 값)만 주고 직접 판정하게 했다. 채점 기준은 규칙 엔진과 같다. 패턴별 탐지 수·경보·오탐·혼동은 반복 평균, 형식 위반·호출 오류는 반복 합계다.

| 판정 방식 | 반복 | 탐지율 평균 (최소~최대) | 급변 | 추세 | 치우침 | 정상 시리즈 경보 | 오탐 사건 | 패턴 혼동 | 형식 위반 | 호출 오류 |
|---|---|---|---|---|---|---|---|---|---|---|
| 규칙 엔진 | 1 | 100% | 7/7 | 7/7 | 7/7 | 1/5 | 6 | 0 | - | - |
| gpt-4.1-mini (temperature 0) | 3 | 67% (67%~67%) | 7/7 | 5.7/7 | 1.3/7 | 5/5 | 103 | 23 | 0 | 0 |
| gpt-6-sol (temperature 기본값) | 3 | 100% (100%~100%) | 7/7 | 7/7 | 7/7 | 1/5 | 6 | 0 | 0 | 0 |

- 형식 위반 출력과 호출 오류는 탐지 0개로 채점했다. 호출 오류가 있으면 실험을 다시 돌려 채운다.

## 4. LLM 설명 검증 (gpt-4.1-mini, temperature 0, 같은 입력 3회)

사건이 있는 시리즈 16개 × 3회 = 출력 48개. 한 출력에 여러 유형의 문제가 있으면 유형마다 센다.

| 항목 | 출력 수 |
|---|---|
| 검증 통과 | 48 |
| JSON 형식 위반 | 0 |
| 원인표 밖 원인 | 0 |
| 판정 불일치 | 0 |
| 호출 오류 | 0 |

- 반복 간 차이: 16개 시리즈 중 0개에서 사건별 1순위 원인이나 점검 순서가 반복마다 달랐다.
- 틀린 출력의 원문 발췌는 `docs/ai_errors.md`에 있다.
- 이번 실험은 JSON 모드 + 자체 검증기를 썼다. 운영에서는 strict 스키마와 원인 id enum으로 형식 위반·원인표 밖 원인을 원천 차단할 수 있다.
- 원인표는 교과서 수준의 도메인 가정이며 실제 설비 데이터로 검증하지 않았다.
