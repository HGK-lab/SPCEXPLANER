구현 계획 Task 11·설계 문서 9절의 화면 설계와 Claude Design 시안을 비교해, 구현 전에 화면 방향을 정한다.

- 비교 대상: **A** 구현 계획의 현재 화면 설계 유지 / **B** Claude Design 설계 전면 채택 / **C** 절충(Streamlit 구조 유지 + Claude Design의 레이아웃·색·문구·정보 배치 차용)
- 자료: `docs/design/claude-design-handoff.md`(공유 프롬프트), Claude Design 프로젝트 "SPC 설명기 UI 디자인"의 `SPC 설명기.dc.html`·`support.js`, `docs/superpowers/plans/2026-09-25-spc-explainer.md` Task 11, `docs/superpowers/specs/2026-09-25-spc-explainer-design.md` 9절
- 확인 환경: Streamlit 1.64.0 (계획 검증에 쓴 버전)

## 1. Claude Design 시안 요약

**형식.** Claude Design 캔버스 문서(`.dc.html`)다. 인라인 스타일의 정적 HTML에 작은 로직 스크립트(`DCLogic`, 차트 좌표 계산)가 붙어 있고, `support.js`는 이 문서를 그리는 React 기반 캔버스 런타임(자동 생성 파일)이다. 실서비스 프런트엔드가 아니라 1440px 고정 폭 목업이며, React·별도 프런트엔드를 새로 만들 것을 요구하지는 않는다.

**화면 3장과 속성 2개.**

| 시안 | 구성 |
|---|---|
| 1a 차트 중심 | 헤더(로고, 역할 띠 "[규칙] 판정 · 정확성 → [AI] 설명 · 해석력", 분석/검증 탭) → 입력 줄(샘플 시리즈, CSV 업로드, 관리 기준 CL/UCL/LCL, "판정 실행") → 왼쪽 관리도 + 오른쪽 440px 패널(규칙 판정 카드 위, AI 설명 카드 아래) |
| 1b 설명 중심 | 같은 헤더(역할 띠 대신 한 줄 소개)·입력 줄 → 관리도 전체 폭 → 아래 3단: **STEP 1 규칙 판정** → 화살표 "판정 결과만 전달" → **STEP 2 AI 설명**(점검 우선순위 카드 3장 가로 배치) |
| 1c 검증 (공통) | 제목 "규칙 판정 vs LLM 단독 판정" → KPI 카드 3장(규칙 탐지율, LLM 단독 탐지율과 차이, AI 설명 오답 건수) → 패턴별 탐지율 막대(규칙 vs LLM) + 해석 → AI 설명 오답 사례 표(입력 패턴, AI 출력, 무엇이 틀렸나, 수정 후 결과) |
| 속성 | `showBands`(규칙 판정 구간 음영 켜기), `aiState`(`cached` 캐시 표시·"↻ 실시간 재생성" / `exhausted` 한도 소진·"재생성 불가") |

**시각 언어.** 규칙은 검정 실선 카드 + "확정" 배지 + "결정적 계산 — 동일 입력이면 항상 동일 결과", AI는 파란 점선 카드 + "AI 생성" 배지 + "참고용 해석 · 판정은 규칙 기준". 패턴은 색과 모양을 같이 쓴다(◆ 급변 빨강, ▲ 추세 주황, ■ 치우침 보라). 관리도의 세로 음영은 "규칙이 판정한 이상 구간"이다. 글꼴 IBM Plex Sans KR / IBM Plex Mono, 배경 회색 `#f3f4f5`, 흰 카드.

**스펙·계획과 어긋나는 점.**

| 시안 | 스펙·계획 | 처리 |

## 2. Streamlit에서 재현 가능한 부분과 불가능한 부분

| 시안 요소 | 재현 | 방법 또는 이유 (Streamlit 1.64에서 확인) |
|---|---|---|
| 색·글꼴·모서리 | 가능 | `.streamlit/config.toml` `[theme]`: `font = "IBM Plex Sans KR:<Google Fonts CSS URL>"`, `codeFont`, `backgroundColor`, `primaryColor`, `textColor`, `baseRadius`. 테마 옵션 52개 확인 |
| 규칙 카드 실선 / AI 카드 점선 | 가능 | `st.container(border=True, key="rule_card")` → 프런트가 `st-key-rule_card` 클래스를 붙인다(1.64 번들에서 확인). 이 클래스에만 CSS를 건다 |
| 헤더 역할 띠, "확정"·"AI 생성" 배지, 고정 문구 | 가능 | `st.html`(iframe 없음, JS 불필요) 또는 `st.badge` |
| STEP 1 → 화살표 → STEP 2 배치 | 가능 | `st.columns([5, 0.7, 7])` |
| KPI 카드 3장 | 가능 | `st.columns(3)` + `st.metric(border=True)` |
| 패턴별 탐지율 막대 | 가능 | Plotly 가로 막대(규칙 vs 모델별) |
| 오답 사례 표 | 가능 | `st.dataframe` 또는 `st.html` 표 |
| 관리도(모양별 마커, 규칙 구간 음영 + 라벨) | 근사 가능 | Plotly `marker.symbol`(diamond / triangle-up / square), `add_vrect` + 라벨. 시안의 SVG를 픽셀 그대로 옮기지는 않음 |
| 캐시 상태 전환(`aiState`) | 가능 | 계획에 이미 있는 세션·하루 호출 한도 로직으로 버튼 비활성·문구 전환 |
| 헤더 바 안의 탭 내비게이션 | 부분 | `st.tabs`는 본문에 그려진다. 헤더 안에 넣으려면 Streamlit 기본 툴바를 CSS로 숨기고 덮어야 해서 내부 DOM에 의존한다 |
| 1440px 고정 폭 픽셀 배치 | 불가 (근사) | Streamlit은 반응형이다. `layout="wide"` 정도로만 맞춘다 |
| 캔버스 런타임(`support.js`, React)·`DCLogic` | 불가 | 편집기용 런타임이다. `st.html`은 JS를 기본으로 무시하고, `unsafe_allow_javascript=True`로 React 런타임을 싣는 건 커스텀 컴포넌트 수준 작업이다. 차트 좌표 계산은 Plotly가 대신한다 |
| CSV 업로드 | 가능하나 범위 밖 | `st.file_uploader` + 입력 검증·테스트가 새로 필요하고 스펙이 제외했다 |

재현이 안 되는 세 가지(헤더 속 탭, 고정 폭, 캔버스 런타임)는 모양의 문제이고, 심사위원이 원칙을 이해하는 데 쓰이는 요소(역할 띠, 실선/점선 카드, STEP 화살표, KPI 카드)는 모두 재현된다.

**마감 판정.** 현재 계획(A)의 남은 구현은 약 4~5시간이다. C는 7.5~9시간으로 9/26 안에 끝난다. B는 11~15시간이라 9/26 안에 들어갈 수는 있어도 여유가 없고, 데모 영상·포트폴리오 작업 시간을 깎는다. 원칙 위반(탭 수, 업로드, 결론 전제)까지 겹쳐 B는 채택하지 않는다.

## 4. 추천: C (절충), 탭 1은 1b(설명 중심) 배치

1. 점수 차이를 만드는 요소(역할 띠, 실선/점선 카드, STEP 화살표, 검증 KPI 카드)는 전부 문구와 배치다. Streamlit 기본 기능으로 재현되므로, 시안의 효과를 거의 다 얻으면서 재현이 어려운 부분만 버릴 수 있다.
2. 시안이 스펙과 부딪히는 부분(CSV 업로드, 탭 2개, 임시 수치와 결론 문장)은 빼고, 스펙이 요구하는 검증 배지·SECOM 탭·3회 반복 보기는 지킨다. Task 1~10은 바뀌지 않는다.
3. 탭 1은 1b를 따른다. "STEP 1 규칙 판정 → 판정 결과만 전달 → STEP 2 AI 설명"이 왼쪽에서 오른쪽으로 읽혀 데모 내레이션과 그대로 맞는다. 1a는 오른쪽 440px 패널에 설명이 세로로 길게 쌓여 촬영 중 스크롤이 생긴다.
4. C는 A 위에 덧칠하는 방식이다. 시간이 모자라면 5절의 순서대로 하다가 멈춰도 그 시점까지 동작하는 화면이 남는다(최악의 경우 A).
